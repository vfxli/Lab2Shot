# 版本号规范

Lab2Shot 的版本号由「版本号」与「阶段」两部分组成，所有组件（服务端 `lab2shot`、`worker_sdk`、网页 `webui`）使用同一个版本。

## 阶段

| 阶段 | 显示名 | 含义 |
|---|---|---|
| Alpha | Alpha 1、Alpha 2… | 早期版本：功能仍在增加，可能存在较多问题，面向愿意试用并反馈的用户 |
| Beta | Beta 1、Beta 2… | 功能基本齐全、不再大改，以修复问题、打磨体验为主 |
| RC（可选） | RC 1、RC 2… | 候选正式版：只修严重问题，没有问题即作为正式版发布 |
| Release | 正式版 | 稳定，可用于生产 |

由 Alpha 进入 Beta、由 Beta 进入正式版，由项目负责人决定。

## 写法

版本号为 `主.次.修订`，遵循语义化版本：

- **主版本**：有不兼容的改动（如数据库、模板、接口无法自动迁移）时加 1。
- **次版本**：新增功能时加 1。
- **修订号**：只修问题时加 1。

阶段写在版本号之后，各处写法如下（以 0.1.0 为例）：

| 阶段 | Python（`pyproject.toml`、`lab2shot/__init__.py`，PEP 440） | 网页（`webui/package.json`，npm semver） | 对外显示 |
|---|---|---|---|
| Alpha 1 | `0.1.0a1` | `0.1.0-alpha.1` | Lab2Shot 0.1.0 Alpha 1 |
| Beta 2 | `0.1.0b2` | `0.1.0-beta.2` | Lab2Shot 0.1.0 Beta 2 |
| RC 1 | `0.1.0rc1` | `0.1.0-rc.1` | Lab2Shot 0.1.0 RC 1 |
| 正式版 | `0.1.0` | `0.1.0` | Lab2Shot 0.1.0 |

## 规则

- 同一阶段内每次发布，阶段序号加 1（Alpha 1 → Alpha 2）。
- 进入下一阶段时序号从 1 开始（Alpha 3 → Beta 1）。
- 正式版发布后，下一个开发周期从新的版本号的 Alpha 1 开始（例如 0.2.0a1）。
- 每次发布同时更新：`pyproject.toml`、`worker_sdk/pyproject.toml`、`lab2shot/__init__.py`、`webui/package.json`，以及中英双语更新说明。
- 扩展接口版本（扩展与核心之间的 API 编号）单独管理，不随本版本号变化。
