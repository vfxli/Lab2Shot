## 这是什么

SegAnyMo 做的是运动物体分割。以往的做法主要靠光流给运动线索，遇到局部运动、复杂形变、运动模糊和背景干扰时预测常常不准。它把长距离轨迹的运动线索和 DINO 的语义特征结合起来，用时空轨迹注意力和运动 - 语义解耦嵌入把运动放在首位、语义作支撑，再用 SAM 2 反复提示，把结果加密到像素级的遮罩。

在 Lab2Shot 里，我们拿它自动找出画面里**真正在动的物体**：走动的人、开动的车、跑的狗、被搬动的箱子，整段镜头每帧交出它们的遮罩，外加一张按物体编号的「物体分割」。它看的是动没动，不是是什么：停着的车、站着不动的人、摆着的道具都不算，哪怕和动的物体是同一类。相机在动也没关系。

## 输入输出

**官方要什么、给什么**（上游自己的话）

- **吃**：现成模型算出的 2D 轨迹和深度图（`third_party/seganymo/repo/README.md:15-16` 的流程总览：「We take 2D tracks and depth maps generated by off-the-shelf models as input」）。
  命令行 `third_party/seganymo/repo/core/utils/run_inference.py` 分三步走（`third_party/seganymo/repo/README.md:84-88`）：`--depths --tracks --dinos` 先算深度图、轨迹和 DINO 特征，
  `--motion_seg_infer` 跑运动分类，`--sam2` 用 SAM 2 把动态轨迹加密成遮罩；`--e` 是高效模式（长边 1000 px，视频保 100 帧）。
- **给**：每帧的运动物体遮罩，同一个物体在整段里归为一组（`third_party/seganymo/repo/sam2/run_sam2.py:595-700` 的 `video_segments` 和 `out_obj_ids`）。

**我们怎么接的**

- 「RGB」口 = 上游的那段素材。上游那三步在一个进程里连着算，帧留在内存里，不写中间文件夹（`adapters/seganymo/worker.py:7-9`）。
  **深度图、轨迹、DINO 特征都是上游自己从同一份画面算出来的**，所以节点上除画面以外没有别的输入口。
- 「运动物体遮罩」= 上游 SAM 2 加密后合成的一张；「物体分割」= `out_obj_ids` 那一套编号（口的标签就叫「物体分割」：「运动」是这个**节点**的事，不是这个**口**的事）。
- 「处理分辨率」= 上游 `--e` 的长边，「分析帧数」= 上游 `--e` 保多少帧做运动分析（遮罩仍然补到每一帧），「查询间隔」= 隔几帧取一个查询帧。
- **不一样的一点**：上游第一步用 Depth Anything V2 Large（CC BY-NC），我们换成 Small。
  实测在 DAVIS / FBMS / SegTrackV2 每个序列上遮罩不变——它的分类器几乎不用那张深度图
  （`traj_oa_depth.gather_point` 按已经归一化到 -1..1 的轨迹去取值，取到的位置是错的，`adapters/seganymo/worker.py:14-20`）。

**出处**：简介抽自论文摘要（arXiv 2503.22268：`We propose a novel approach for moving object segmentation that combines long-range trajectory motion cues with DINO-based semantic features and leverages SAM2 for pixel-level mask densification through an iterative prompting strategy.`
和紧接着那句 Spatio-Temporal Trajectory Attention / Motion-Semantic Decoupled Embedding）；
输入输出依据 `third_party/seganymo/repo/README.md:15-18、:84-88`、`repo/sam2/run_sam2.py:595-700` 和 `adapters/seganymo/nodes.py:24-26`（口由分割家族 `lab2shot/nodes/families/segmentation.py` 给）、`adapters/seganymo/worker.py:7-33`。

## 在 Lab2Shot 里怎么用

- **给相机解算挡掉运动物体**（主要用途）：「运动物体遮罩」接到 COLMAP、VGGT、Pi3、MapAnything…… 的「运动物体遮罩」输入，解算只用不动的背景。建议中间接「遮罩调整」扩边 10–20 px，把运动模糊的边也挡住。
- **按物体挑**：「物体分割」接「分割转遮罩」，只要某一个动的物体（运动物体 1、运动物体 2……）。
- **给抠像当引导**：运动物体遮罩接 MatAnyone 2 的「粗遮罩」，得到带软边的 alpha。
- **深度图**：内置 Depth Anything V2 Small（原作者用的是只能非商用的 Large）。我们试过把 Video Depth Anything 的视差、MoGe 的深度图接进去替换它：在 DAVIS、FBMS、SegTrackV2 的 9 段有标准答案的片段上，遮罩一模一样（原作者的运动分类网络几乎用不上深度图：它按归一化到 −1..1 的坐标取深度图数值，左上四分之一的点都取到角上的像素），所以节点没有深度图输入。
- **和 SAM 3 / VidEoMT 的区别**：SAM 3 按词找（“car” 会把停着的车也抠掉），VidEoMT 按类别分；SegAnyMo 只要动的。给相机解算挡物体时，停着的车是好的特征点，不该挡掉，这正是 SegAnyMo 的用处。
- **参数**：
  - **处理分辨率**：长边缩到多少像素再分析，默认 1000（原作者的效率模式）。遮罩始终输出原画面大小。
  - **分析帧数**：判断谁在动时看多少帧，从整段里均匀挑，默认 100（原作者的效率模式）；遮罩还是每帧都有。长镜头里有物体只在一小段动，调大。
  - **查询间隔**：每隔多少个分析帧撒一次跟踪点，默认 10。物体只出现很短时间时调小。

## 效果和局限

（RTX 4090 实测见下；数字来自本机测试。）

- 原作者在 48 GB 显卡上开发；Lab2Shot 用原作者的效率模式（长边 1000、最多 100 帧分析），24 GB 显卡够用。
- 画面里什么都没动时，输出空遮罩并提示（原作者的代码这时会硬挑 3 个最像在动的点当作一个物体，Lab2Shot 不这样做）。
- **只留把握最大的运动物体**：它按原作者的做法，从 0.95 往下找能挑出至少 10 个跟踪点的最高把握，所以画面里同时有几个在动的物体时，动得明显、占画面大的那个一定在，动得慢、小、远或只在画面里经过一瞬的可能漏掉（实测：DAVIS scooter-black 里经过的银色汽车、crossing 里两个过马路的人中的一个、sh020 里从门里走出来的老人都没抠到）。把门槛固定调低（试过 0.5）会把路面和停着的摩托车也抠进来，更糟，所以没有做成参数。给相机解算用时，漏掉的可以用 SAM 3（按 person / car）或「人物框转遮罩」补上，再用「遮罩合并」合在一起。
- 物体动得很慢、或者只动了一小会儿，可能判成不动：调大「分析帧数」、调小「查询间隔」。
- 编号是按物体找到的先后，不代表类别；同一个物体被挡住很久再出现时可能拿到新编号，也可能被合并。
- 遮罩的边来自 SAM 2，适合挡解算和做 roto 起点，不是精细抠像。

## 模型下载和安装

- 运行 `uv run lab2shot ext install seganymo`，会下载：
  - 运动分类模型 moseg.pth（14 MB，Hugging Face Changearthmore/moseg）；
  - SAM 2 Hiera-L（0.9 GB）、BootsTAPIR（0.2 GB）、DINOv2 ViT-B/14（0.3 GB）、Depth Anything V2 Small（0.1 GB）；
  - 一个独立的 Python 环境（PyTorch 2.9 + CUDA 13），安装时现场编译 SAM 2 的 CUDA 核（填洞用），需要几分钟。
